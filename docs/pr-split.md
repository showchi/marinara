# MV3 修复的 PR 拆分

## PR 1：基础修复与原有浏览器兼容性

当前工作区对应这一范围：

- 保留 `tabs` 权限和最低 Chrome 116。
- 通过标签页查询复用设置页、倒计时页，并清理旧提醒页，包括 discarded 标签页。
- 移除 `node-sass`，为现有 webpack 4 构建提供进程级 OpenSSL 兼容选项。
- 将计时状态迁移到 `storage.session`，清理旧的 local 计时快照，保留设置与历史。
- 保留通知资源 URL 修复；隔离桌面通知、提醒标签页和历史统计失败；移除过时的 `isClickable`。

权限优化不作为这些修复的发布前提，也不提高最低浏览器版本。

验证记录（2026-11-08）：76 项单元测试通过；生产构建通过，保留原有 bundle 大小警告。Chrome 116.0.5845.96 和 157.0.8103.39 的隔离浏览器回归通过：discard 后复用设置页和倒计时页、worker 重启后清理 discarded 提醒页。浏览器会话恢复后的未加载标签页场景尚未单独实测。

## PR 2：独立移除 tabs 权限

这是后续实现范围，不属于当前 PR。基于 PR 1，继续保持 Chrome 116 兼容；不采用要求 Chrome 153.0.8010.52 的无权限 URL 查询方案。

需要独立落实的页面行为：

- 设置页：优先验证 `runtime.openOptionsPage()`，并处理设置、历史、反馈子路由的切换。
- 倒计时页：重新设计打开和关闭行为。若取消复用，需要明确处理 `autoclose: false`，避免每个阶段自动累积窗口；不能默默改变用户已有设置。
- 提醒页：移除依赖标签页 URL 扫描的清理逻辑。活动页面应响应计时状态变化；页面加载或恢复时应校验提醒是否仍有效，关闭或禁用失效操作。
- 无权限方案无法仅靠活动文档发现未加载旧标签页。若允许旧标签暂时保留、恢复时再处理，必须明确记录这个行为差异。

独立验收应覆盖最低版本和当前版本：设置子路由切换、连续多个计时阶段、倒计时自动关闭开关、worker 重启、discard、浏览器会话恢复，以及旧提醒不能触发失效操作。

两个 PR 应顺序合并；第二个 PR 不要求第一个 PR 先提高最低版本。
